Audience and promise

Helm serves people who already run Hyprland, from GUI-oriented newcomers to expert configuration authors. Its defining promise is safe management of existing settings from one place. Common controls lead with intent; source files, raw keys, ownership, capabilities, and exact effects remain available through progressive disclosure.

Interaction

The GUI is primary and the CLI is first-class. A setting change immediately starts an isolated transaction and visibly progresses through validation, application, verification, success, rollback, or conflict. Display changes use a 15-second keep-or-revert watchdog. History records semantic changes and exact diffs; restoration creates a new transaction.

1.0 modules

  • Overview, discovery, diagnostics, search, history, and undo
  • Appearance, semantic themes, and wallpaper
  • Hyprland general settings, displays, keybindings, and window rules
  • Alacritty, Yazi, Waybar, and cooperative Quickshell
  • Startup applications, MIME/URI defaults, and atomic profiles
  • Sandboxed third-party plugins with native declarative UI

Boundaries

Helm 1.0 is local-first, English-only, user-scoped, Arch-native, and Hyprland-only. It has no telemetry, account, root helper, package manager, persistent daemon, online marketplace, or background update check. Accessibility qualification, localization, additional compositors, Flatpak, legacy config migration, system settings, and video wallpapers remain later work.
